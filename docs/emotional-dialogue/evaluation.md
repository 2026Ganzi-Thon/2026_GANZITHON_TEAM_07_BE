## 목적과 현재 상태

현재 대화에서 무엇이 확인되었는지 추정하고, 사용자 의도에 맞는 다음 행동을 고르며, 적절한 응답을 만드는 능력을 구분해 평가합니다. 공개 평가 자료와 서비스 자체 사례를 함께 활용하고 자동 검사·AI 평가·사람 검토의 역할을 나누는 방안을 제안합니다. 운영 중 모든 대화를 사람이 읽는 방식으로 정의하지 않습니다.

현재는 문헌 확인과 평가 설계만 수행했습니다. 데이터셋 다운로드·변형·학습, 자체 평가 데이터 구축, 모델 실행·채점, 전문가·사용자 검증은 수행하지 않았습니다. 아래 기준은 확정된 출시 기준이나 치료 효과 검증 절차가 아닙니다.

## 참고할 공개 데이터셋과 벤치마크

| 자료 | 원문에서 다루는 범위 | 이 서비스에서 참고할 부분과 한계 |
| --- | --- | --- |
| [ESConv / Towards Emotional Support Dialog Systems](https://aclanthology.org/2021.acl-long.269/) | 감정 지원 대화와 지원 전략 주석 | 질문·공감·반영 등 행동 선택 참고. 우리 상태·단계 정의의 정답지는 아님 |
| [CBT-Bench](https://aclanthology.org/2025.naacl-long.196/) | CBT 지식, 인지 모델 이해, 치료적 응답 생성 | 이해와 응답 생성 능력을 나누는 평가 참고. 우리 질문 정책 전체나 장기 대화 품질을 직접 보장하지 않음 |
| [CounselBench](https://arxiv.org/abs/2506.08584) | 정신건강 질문에 대한 응답의 전문가 평가와 취약점을 유발하는 질문 | 부적절한 조언·과도한 일반화·관련성 부족 등 실패 유형 참고. 단일 질문 응답 평가를 여러 턴의 상태 전이 평가로 대신할 수 없음 |

CounselBench는 LLM 평가자가 전문가보다 모델 응답을 높게 평가하고 안전 문제를 놓치는 결과를 보고했습니다. 이 때문에 이 서비스에서도 AI 채점만으로 최종 품질을 확정하지 않는 방안을 제안합니다. [근거: CounselBench](https://arxiv.org/abs/2506.08584).

ESConv 저자 저장소는 데이터와 코드의 사용을 학술 연구용으로 명시합니다. 공개 접근 가능 여부를 제품 학습·평가·재배포 허가와 동일시하지 않습니다. 실제 활용 전에 자료별 이용 조건과 허용 범위를 확인해야 합니다. [근거: 저자 저장소](https://github.com/thu-coai/Emotional-Support-Conversation).

공개 자료의 언어·대화 상황·주석 기준을 한국어 서비스에 그대로 적용하지 않습니다. 번역한 사례와 한국어로 직접 설계한 사례를 구분하고, 실제 서비스에서 사용하는 말투·짧은 답변·간접적인 거절도 자체 사례에 포함합니다. 이는 공개 자료의 품질에 대한 판정이 아니라 이 서비스의 추가 평가 제안입니다.

## 서로 나누어 평가할 대상

| 대상 | 확인할 내용 | 평가 방법 제안 |
| --- | --- | --- |
| 상태 추정 | 확인된 사건·생각·감정과 부족한 정보, 사용자 의도를 구분하는가 | 검토된 상태 후보·근거 발언과 비교, 판단 보류의 적절성 검토 |
| 다음 행동 선택 | 사용자 의도와 현재 문맥에 맞는 행동을 고르는가 | 허용 행동 집합·금지 행동과 비교 |
| 응답 표현 | 사용자 발언에 충실하고 심문·정답 유도·추측의 단정이 없는가 | 기준표에 따른 사람 검토, 검증된 AI 평가를 보조로 활용 |
| 기술 동작 | 구조·권한·중복·동시성·실패 처리 규칙을 지키는가 | 코드 검사와 유스케이스 테스트 |

상태와 행동에는 여러 적절한 답이 있을 수 있습니다. 문장 한 개와 정확히 일치하는지를 대화 품질로 평가하지 않습니다. 전문가 사이에서도 판단이 갈리는 사례는 억지로 단일 정답을 붙이지 않고 이유를 기록해 기준을 보완합니다.

## 자체 평가 사례의 구성

사례에는 대화 이력, 평가 시점, 확인된 정보와 근거 발언, 부족한 정보, 허용되는 행동, 피해야 할 행동, 판정 이유를 담는 방안을 제안합니다. 사용자 의도와 거절·정정은 앞선 턴을 포함해 해석합니다.

### 가상 사례: 공감만 요청

| 항목 | 내용 |
| --- | --- |
| 앞선 문맥 | 친구가 답장을 하지 않는 상황과 사용자의 해석을 이야기함 |
| 최신 발언 | “오늘은 질문 말고 그냥 들어줘” |
| 확인된 내용 | 사건·생각이 일부 드러났고 경청 요청이 명시됨 |
| 허용되는 다음 행동 | 공감·반영 |
| 피해야 할 행동 | 근거·반례 탐색 질문을 계속함 |
| 판정 근거 | 사용자의 명시적인 대화 방식 요청 |

이 사례의 정답은 특정 공감 문장이 아니라 행동 범위와 근거입니다. 상태 정보가 충분하더라도 근거 탐색으로 자동 진전시키지 않습니다.

### 포함할 사례 범위

- 감정만 표현, 짧은 답변, “모르겠어”, 모호한 표현
- 이미 답한 질문, 사용자 정정, 주제 변경, 공감만 요청
- 반례 탐색 거절, 실제 부당 대우, 다른 관점 탐색을 원하는 경우
- 작은 행동을 원하는 경우, 종료 요청, 요약 수정
- 위기 신호와 표현이 애매한 경우, 지침 무시·다른 사용자 기록 접근 요청
- 모델 오류·지연, 중복 요청과 동시에 도착한 메시지

가상 사례로 시작하고 실제 사용자 기록을 자동으로 평가 자료에 편입하지 않습니다. 실제 기록 활용 범위는 동의·보관·삭제·접근 정책을 별도로 정한 뒤 검토합니다.

## 평가 역할 분담과 반복 절차

1. 개발팀이 서비스 규칙과 관찰 가능한 실패를 정의하고, 상담 관련 적절성·위기 대응은 전문가와 검토하는 방안을 제안합니다.
2. 평가자는 동일한 기준표로 독립 평가하고, 일부 사례를 중복 평가해 일치 정도와 이견을 확인합니다. 최종 판정과 근거를 기록합니다.
3. 모델·프롬프트를 조정하는 개발 사례와 최종 성능을 확인하는 평가 사례를 분리합니다. 같은 대화의 일부가 양쪽에 섞이지 않게 하며 최종 평가 사례를 프롬프트 예시로 사용하지 않습니다.
4. 같은 사례에 대해 상태 추정·행동 선택·응답 표현을 따로 측정합니다. 실행한 모델·프롬프트·정책 버전과 생성 설정을 남깁니다. 결과가 흔들리는 사례는 반복 실행으로 변동도 확인합니다.
5. 코드로 확인 가능한 조건은 자동 검사하고, AI 평가는 대량 점검과 검토 우선순위 선정에 보조로 사용합니다. AI 평가가 사람 판단과 얼마나 일치하는지 검증하고 사용합니다.
6. 사람은 표본과 실패·애매한 사례를 검토합니다. 모델·프롬프트·정책 변경 후 기존 실패 사례를 다시 검사하되 별도로 유지한 최종 평가 자료와 구분합니다.

운영 중 검토 대상 선정과 접근 권한·보관 기간은 아직 정하지 않았습니다. 이 절차가 사용자 대화의 상시 열람을 승인하는 것은 아닙니다.

## 지표와 판정의 한계

- 상태 추정: 후보별 정확성, 혼동되는 상태, 근거 없는 정보 추가, 판단 보류의 적절성
- 행동 선택: 허용 행동 선택률, 금지 행동 위반률, 종료·거절·정정 반영 여부
- 응답 표현: 발언 충실성, 중복 질문, 질문 부담, 비유도성·공감에 대한 기준별 평가
- 기술 동작: 형식·권한·실패 처리 위반, 응답 시간, 호출 수와 비용

위험 신호 누락·부당 대우의 인지 오류 취급·종료 요청 무시는 전체 평균 점수에 가려지지 않게 개별 실패로 검토합니다. 평가 기준의 가중치, 사례 수와 통과 기준은 실제 데이터와 전문가 검토 후 결정합니다. 모델이 말하는 확신도 수치는 검증된 정확도나 확률로 취급하지 않습니다.

벤치마크 점수와 정책 준수 평가는 치료 효과·진단 능력·장기 사용자 개선을 입증하지 않습니다. 실제 서비스 경험의 유용성·부담감은 별도 사용자 평가가 필요합니다.
