# Domain docs

## Layout

Single-context: root GLOSSARY.md and docs/adr/.

## Consumer rules

Before exploring, read GLOSSARY.md if present and ADRs relevant
to the work under docs/adr/.

If these documents are absent, proceed silently.
Create them through domain-modeling when actual terms or
decisions are resolved.

Use glossary terms consistently in issues, code, and proposals.
Surface conflicts with an existing ADR explicitly.
