# 공유 팀 저장소 협업 전환 스펙

기록일: 2026-11-01. 기반 작업이며 업무 기능 변경은 없습니다.

## 합의

사용자는 회사에서 흔히 쓰는 단일 팀 저장소·작업 브랜치·PR 방식을 요청했고 fork를 사용하지 않는다고 명시했습니다. 이 결정이 기존 fork 필수 지침을 대체합니다.

## 범위와 완료 조건

- 팀 저장소를 origin 하나로 사용하고 main 추적과 push 기본값 정리
- 기존 커밋·작업 브랜치·stash·로컬 백업 보존
- 작업 브랜치 직접 push 허용, main 직접 push·태그·삭제·다른 저장소 차단
- 훅의 실제 Git 환경 회귀 검사 제공
- AGENTS·README·협업·PR·VS Code·이슈 문서와 현재 협업 스펙 동기화
- Java 21·MySQL 8.4 및 훅 검사를 PR CI로 구성
- 팀 작업 브랜치 push와 같은 저장소 PR 생성까지 확인, main merge는 수행하지 않음

## 확인한 환경

팀 main과 로컬 main은 `6d4e354`로 일치합니다. 현재 사용자는 WRITE 권한입니다.
main 서버 보호는 꺼져 있으며 관리자 권한이 필요한 보호 설정은 변경하지 않습니다.
설정 방법은 [전환 가이드](../../docs/shared-repository-migration.md)에 남깁니다.
