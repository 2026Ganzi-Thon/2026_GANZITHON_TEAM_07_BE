# 감정 탐색 서비스 스펙

상태: 핵심 목적 합의, 상세 기능 계약과 MVP 범위 미정. 기록일: 2026-11-01.

## 합의한 핵심 경험

사용자가 감정을 말하면 AI가 후속 질문을 계속 생성하여 사용자가 내면에 어떤 감정이 있었는지 탐색하도록 돕습니다. AI가 감정을 확정적으로 판정하는 기능으로 정의하지 않습니다.

개념 흐름: 감정 표현 → AI 질문 → 사용자 답변 → 이어지는 AI 질문. 질문 생성 전략, 대화 문맥 유지 방식과 종료 조건은 아직 정하지 않았습니다.

## LLM 결정 상태

사용자 요청에 따라 제공자, 모델명, API 키는 빈 값으로 유지합니다. SDK·프롬프트·질문 생성 API·모델 호출은 추가하지 않았습니다. 특정 업체나 모델, 외부 호출 비용은 승인하거나 확정하지 않았습니다.

## 기능 구현 전에 정할 사항

- MVP에 포함할 기능과 우선순위
- 대화 시작·종료 기준, 질문 수와 질문 전략
- 답변을 다음 질문에 반영하는 문맥 범위
- 사용자 식별과 인증·권한
- 감정·질문·답변의 저장 시점, 열람·수정·삭제·보관 정책
- 요청·응답 계약, AI 실패·지연 처리
- 음성 처리와 클라이언트·백엔드의 책임
- 조언·추천·분석의 입력 및 출력 기준

상세 배경과 사용자 흐름은 [서비스 기획안](../../docs/service-overview.md), 기능별 요구사항은 [기능 명세서](../../docs/features.md)를 기준으로 이어갑니다.

## 2026-11-03 기획 원문 보완

사용자가 다시 제공한 기획서에서 기존 문서에 생략된 다음 내용을 제품 문서에 반영했습니다.

- F-01~F-04: CBT·소크라테스식 문답·SFBT 참고 방향, 대화 분석 대상, 감정·상황 구체화라는 종료 방향
- F-05~F-06: 메인 화면에서의 진입 선택, 종류 변경, 말랑이별 터치·드래그·복원 규칙, 감정별 추천 방향
- 커스텀 사진 기능은 개발 우선순위에서 제외한다는 원문 내용

이 보완은 기획 원문을 기록하는 문서 작업입니다. F-01~F-10 구현 상태와 MVP 미정 상태는 유지합니다. 구체적인 종료 판정, 말랑이 명칭 대응, ASMR 사운드, 보관·삭제 정책과 전체 MVP 범위를 새로 확정하지 않았습니다.

사용자 요청에 따라 작업 브랜치에서 커밋하며, 원격 푸시와 PR 생성은 보류합니다.

## 2026-11-03 AI 대화 제어 설계 검토

사용자는 소크라테스식 대화·CBT·SFBT 자료를 제시하고, 사용자 대화에 이를 도입하며 BE가 AI를 제어하는 에이전틱한 구성이 가능한지 질문했습니다.

- [설계안](../../docs/emotional-dialogue/design.md): 제한된 대화 행동 선택, BE의 상태·권한·응답 검증, 실패 처리와 평가 방법을 제안합니다.
- [조사 기록](../../docs/emotional-dialogue/research.md): 기법과 워크플로의 근거, 임상 표준·치료 효과로 확대 해석할 수 없는 한계를 구분합니다.

대화 방식·정책은 검토 단계입니다. 구현, 모델·업체 선택, 외부 호출 비용, 공개 API·스키마·데이터 보관 정책을 확정하지 않았습니다. 기존 `docs/service-planning` 브랜치에서 이어서 문서만 커밋하고 푸시·PR 보류 요청을 유지합니다.

사용자의 문서 위치 정리 요청에 따라 설계안과 조사 기록을 `docs/`로 옮기고 README·기능 명세서·아키텍처의 링크를 연결했습니다. 이 파일에는 작업 맥락을 남기며 상세 내용은 해당 문서를 기준으로 유지합니다.

## 2026-11-03 감정 대화 문서 분리와 평가 설계 추가

사용자는 평가 데이터셋·사람 평가 설명을 문서로 추가하고 감정 대화 전용 폴더로 관리한 뒤 PR을 생성하도록 요청했습니다. 앞서 보류했던 푸시·PR을 이번 요청으로 진행합니다.

- [감정 대화 문서](../../docs/emotional-dialogue/README.md): 설계·조사·평가를 `docs/emotional-dialogue/`에서 관리합니다.
- [평가 설계안](../../docs/emotional-dialogue/evaluation.md): ESConv·CBT-Bench·CounselBench의 범위, 자체 평가 사례와 역할 분담을 정리합니다.
- 대화 상태 추정과 다음 행동 선택을 구분하고 판단 보류·근거 발언과 평가 한계를 설계안에 보완합니다.

문서 작성만 수행하며 실제 모델 평가·데이터 구축·업무 기능 구현 상태는 바꾸지 않습니다.
